# Making a Glory post

A post is a four-slide carousel about one edge of the knowledge graph: two
verses and the sentence explaining how they relate. Every word comes from
content this repo already verifies. Nothing is generated by a model.

That is not squeamishness. `scripts/verify-quotes.mjs` only guards
`questions.ts` and `connections.ts`. A model-written caption bypasses the
verifier entirely, and a misquote on a public account cannot be recalled. The
account's whole claim is exactness, so it is the last place to improvise.

Read `AGENTS.md` for the data model. This skill is the editorial rules and the
trap list.

## Pipeline

```bash
npm run export:social                      # 30 drafts into social/posts + queue.md
npm run export:social -- --dry-run         # print the queue, write nothing
npm run export:social -- --why "John 8:58" # why an edge did or did not make it
npm run export:social -- --check           # verse text and notes against their sources
npm run export:social -- --mark 001 002    # record what published, archive the drafts
npm run export:social -- --force           # rebuild the queue from scratch
npm run export:social:cards                # draw the PNGs
npm run export:social:cards -- --only 007  # draw one draft
```

| path | what it is | in git |
| ---- | ---------- | ------ |
| `social/posts/` | the live queue of drafts | yes |
| `social/posted/` | published drafts, archived on `--mark` | yes |
| `social/state.json` | the published-pair ledger | yes, it is the thing that stops repeats |
| `social/cards/` | 1080x1350 PNGs | no, redraws in seconds |
| `fonts/` | the ttf faces the renderer needs | yes |

## Card order: claim first

| slide | shows |
| ----- | ----- |
| 1 | the kind label, the connection note, the ref pair |
| 2 | the **earlier** verse, in canonical book order |
| 3 | the verse that quotes or fulfils it |
| 4 | `KEEP READING`, the study question, `glorystudy.com` |

Which is a rotation of the original verse-first order (`COVER = "verse"` at the
top of `scripts/export-social.mjs`), where slide 1 was a verse and slide 3 the
note. Keep both: they are worth comparing over ten posts by saves and shares,
not by argument.

Why claim first:

- Most viewers see only slide 1. A verse screenshot is generic; "Peter is
  quoting the servant song" is the one thing on the platform nobody else has.
- It fixes the weak cover. Verses lifted out of a chapter open mid-sentence
  (`who his own self bore our sins...`), and eight of thirty did. Claims do not.
- Canonical order makes the reveal run forward: the psalm, then the letter that
  quotes it. Canonical order is not chronology, so never argue dates from it.
- Ending on a question moves. A note is a full stop.

The cost, which is real: the grid stops looking like scripture and starts
looking like claims in our voice. Decide that with the grid in front of you.

## The cover test

A note was written to sit *after* the verses. On a cover it has to stand alone.

The exporter scores down and flags notes that point backwards:

```
002  Hebrews names this faith among those who stopped the mouths of lions.
017  The argument rests on the psalm's oath about an order of priesthood...
026  Paul quotes this sentence and applies it to the word of faith he preaches.
```

`POINTS_BACK` in the exporter catches "this faith", "this sentence", "The
argument rests on". It cannot catch a cover with no verb, such as:

```
The psalm that asks for the betrayer's days to be few and for another to take his office.
```

That one is a noun phrase, not a claim. Read every cover in `queue.md` and check
for a subject and a verb before rendering.

When a note fails, fix the note in `src/data/connections.ts`, never in the draft,
so the study page gets the improvement too. Often there is a twin edge in the
other direction whose note already works: the scheduler picks it automatically
once the weak one is scored down.

## Rules that only bite later

**A caption has no clickable link, ever.** Not at any follower count. A url in a
caption is a dead string nobody taps and nobody retypes. Captions end:

```
Read the study: <the question>
Link in bio.
```

Slide 4 therefore names the bare host, not the study's deep path, because the
bio link lands on the front page. The deep link lives in the draft under
`## Slide 4`, for you. Stories are the exception: they have a link sticker.

**Alt text is per image, not per post.** The draft prints one numbered line per
slide for that reason. Paste them one at a time in Advanced settings.

**A feed thumbnail may crop 4:5 to a square.** Keep anything essential inside
the central 1080 square. That is why `COUNTER_Y` is not nearer the edge.

**Never hand-edit a verse in a draft.** `--check` compares every draft against
the vendored WEB and against `connections.ts`, and the renderer refuses to draw
a draft that has drifted. If a verse needs changing, the data is wrong.

**Do not regenerate per post.** `--force` rebuilds and renumbers the whole
queue. Post from the batch, mark as you go, and regenerate when it runs dry.
Numbers are filing, not history: `state.json` is the history.

**Marking archives the draft and records the pair.** Pairs are deduplicated in
both directions, so an edge cannot come back by flipping source and target.

**Instagram cannot swap images on a published post.** To redo one, delete it,
then remove its entry from `social/state.json` and move the draft back from
`social/posted/` (or just clear state and `--force`) so it can be selected
again.

**Uncommitted studies leak into drafts.** The generator reads the working tree,
so a study you have not deployed can be picked as the study for a post. Slide 4
only prints the bare host, so the card is safe; it is the draft's `Study page:`
link and the question in the caption that point at a page that does not exist
yet.

**Hashtags.** `HASHTAGS` is a fixed block of five. Five is plenty; thirty reads
as spam and the platform does not reward it.

## Posting by hand

On the web uploader: `Create` -> `Post` -> `Select from computer`, then paste the
folder path into the file dialog (`Ctrl+L` in GTK). Select all four in order.
Do not drag files onto the page; the browser navigates to the image and you lose
the tab.

Set the crop to **4:5**, not square, or the top and bottom are cut. You can tell
it is right when the ref label at the top and the counter at the bottom are both
visible. Paste the caption, add alt text per slide, share, then `--mark`.

## Geometry

`ROOM_*` constants and the per-slide size lists at the top of
`scripts/render-social-cards.mjs` are the entire layout. There is no other layout
logic. Type is auto-fitted: the renderer tries sizes descending and takes the
first that fits, and says so loudly if even the smallest overflows, because a
clipped verse is the one failure a quotation card must not have.

The palette is copied by hand from `src/app/globals.css`. Em dashes are banned
in our copy (scripture's own punctuation is exempt, it is quoted text).

## Guards the scripts enforce for you

These exist because each one has already gone wrong once:

| guard | what it stops |
| ----- | ------------- |
| corrupt `state.json` stops the run | silently re-offering every published edge |
| ledger written to a temp file and renamed | a half-written ledger after an interrupt |
| record persisted before the draft is archived | a crash marking a post twice |
| archive collision refuses to overwrite | one published draft destroying another |
| `--mark` matches digits plus a hyphen | `--mark 01` claiming post 010 |
| `--count` must be an integer in range | `--count 2O` emptying the queue under `--force` |
| missing fields skip a draft with reasons | one malformed draft aborting the whole render |
| the renderer re-checks the note, not just the verses | a cover saying something `connections.ts` does not |

## Traps that cost real time

- **A script that edits drafts must find the caption fence by parity.** The
  opening ```` ``` ```` is preceded by a blank line, so a naive
  "fence after a blank line is the closing one" check closes on the opening
  fence and corrupts every caption below it.
- **Instagram rate-limits anything scraped from one IP.** Username availability
  and profile checks return 429 from a script. Use the app's own Edit profile
  screen, which answers instantly and authoritatively.
- **Basing a decision on one published post is not a comparison.** One data
  point is taste. Ten split across two formats starts to be evidence.
